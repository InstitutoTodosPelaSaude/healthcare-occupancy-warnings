# Healthcare occupancy data as an early warning indicator of infectious disease surges

Code and data to reproduce the analyses in:

> **Healthcare occupancy data as an early warning indicator of infectious disease surges in the São Paulo metropolitan area, Brazil**

The study analyses hourly occupancy data from 17 public urgent care units in the
São Paulo metropolitan area, collected between 15 July 2023 and 12 October 2024,
and compares it with laboratory-confirmed surveillance data for SARS-CoV-2,
dengue virus and a panel of respiratory viruses of public health importance.

Every figure and supplementary table in the manuscript is regenerated by the
pipeline in `scripts/`.

## Installation

```sh
conda create --name occupancy python=3.12.9
conda activate occupancy
pip install -r requirements.txt
```

`dtaidistance` benefits from its compiled backend. If the wheel does not provide
it on your platform:

```sh
pip install -vvv --upgrade --force-reinstall --no-deps --no-binary dtaidistance dtaidistance
```

## Running the pipeline

Scripts are numbered and run in order. Paths are resolved relative to the
repository, so they work from any working directory:

```sh
python scripts/01_unit_overview.py
python scripts/03_consolidate.py
python scripts/04_dtw_alignments.py
python scripts/05_granger_waves.py
python scripts/06_volatility_index.py
python scripts/07_lead_time_analysis.py
python scripts/08_spatial_associations.py
python scripts/09_unit_map.py
python scripts/10_export_supp_tables.py
```

Step `02_public_surveillance_etl.py` is optional: it documents how the public
surveillance series in `data/public_cases/` were built and re-downloads the raw
dumps. It is not needed to reproduce the results (see *Data* below).

Each file carries `# %%` cell markers, so it can also be stepped through in
VS Code's interactive window or converted to a notebook.

## What each step produces

| Step | Output | Manuscript item |
|---|---|---|
| `01_unit_overview` | daily and weekly occupancy panel, clustered heatmap | Figure 2A |
| `02_public_surveillance_etl` | weekly SIVEP-SRAG and InfoDengue series | (input data) |
| `03_consolidate` | weekly occupancy joined with all laboratory indicators | Table S2 |
| `04_dtw_alignments` | DTW warping paths and distances | Figure 3 |
| `05_granger_waves` | ADF stationarity and Granger causality by wave | Table S3 |
| `06_volatility_index` | 42-day z-scores, per-unit barplots and status maps | Figure 4A-C, E-F |
| `07_lead_time_analysis` | alert weeks, laboratory peaks, lead times | Figure 5, Tables S5-S6 |
| `08_spatial_associations` | Haversine distance matrix, LISA clustering | Figures S1, S2, Table S4 |
| `09_unit_map` | locator map of the 17 units | Figure 1A |
| `10_export_supp_tables` | Supplementary Tables S1-S6 (TSV and XLSX) | Tables S1-S6 |

Results are written under `results/`; the supplementary tables land in
`results/supp_tables/`.


## Data

Occupancy percentages were obtained from Google Maps for 17 public urgent care
units. The values are aggregated and anonymised at source and contain no
individual-level information.

Laboratory surveillance data come from three sources: the ITpS private
laboratory network (exploratory data, weekly positivity rates), SIVEP-SRAG via
Open Datasus and InfoDengue (both validation data, weekly case counts). The
public series were retrieved on 6 April 2025.

A few notes on the shipped files:

- The weekly ITpS positivity series in `data/private_labs/` are the pipeline's
  starting point for the private laboratory data; the upstream ETL that produced
  them is outside this repository. These are the same data reported in Table S2.
- Both public sources are revised retrospectively, so re-running step 02 yields a
  current snapshot rather than the April 2025 one. It writes to
  `data/public_cases/refreshed/` to leave the published series untouched.
- Final manuscript figures were composed from the outputs of these scripts;
  panels 1B and 1C are schematics.
- Occupancy data are provided as collected, at hourly resolution, as described in
  the Methods.

## Reproducibility notes

- LISA p-values come from conditional randomisation. `08_spatial_associations.py`
  fixes the random seed so the step is deterministic. The p-values published in
  Table S4 came from an unseeded run, so they differ in the third decimal;
  cluster assignments and significance calls are unaffected.
- All other steps are deterministic and reproduce the published tables exactly.
